一、项目背景与阶段目标

1.1 项目来源

本工程源自开源项目 ckflight/FMCW3：一颗 Xilinx Artix-7（原设计为 FTG256 封装）负责 FMCW 雷达的数字后端——ADC 采集、FIR 抽取、斜坡（ramp）时序控制、USB 上传，配合 ADF4158 锁相环与 LTC2292 双通道 ADC 组成一套 5.8 GHz FMCW 雷达前端。

1.2 本阶段要解决的问题

我手上没有射频前端（没有 ADF4158、没有 LTC2292、也没有原设计的 FT2232H 双通道 USB 芯片），但有一块 XC7A35T-FGG484 开发板。因此本阶段的目标是：

在不接任何射频硬件的前提下，用 FPGA 内部产生的"假 ADC 数据"，把原工程的数字后端完整搬到这块板子上跑通，一直做到 PC 端能接收、能切帧、能做 FFT。

这条链路一旦跑通，"有真实射频前端"只是把假数据换成真数据的问题，数字链路本身不再有未知数。

1.3 本报告覆盖的判据

本阶段结束时应能回答四个问题：

  1. 数据是否真的从 FPGA 走到了 PC？（字节数、速率）
  2. 走过来的数据对不对？（采样率、数值连续性、增益）
  3. PC 端能否把字节流切成"一帧 = 一个 chirp"？（帧同步）
  4. 对每帧做 FFT，结果是否与已知的信号特征吻合？（数值链路正确性）

四个问题在本报告中全部得到肯定答复，详见第三、五章。

三、已完成的步骤（详细）

3.1 环境与器件核对

  • 原工程 part 为 xc7a35tftg256-1（FTG256 封装），与本板 FGG484 封装不符，改为 xc7a35tfgg484-2；Block Design 内的器件字段同步更新。
  • 改 part 后 Vivado 报 "IP is locked"（IP 与器件绑定），用 upgrade_ip [get_ips] 与 generate_target all 解决。
  • 硬件差异核对：原设计用 FT2232H（双通道，A 通道做 FIFO、B 通道做 JTAG）；本板是 FT232H（单通道 FIFO）+ CH340（串口）+ 独立 10 pin JTAG 排针。因此 JTAG 下载器与 USB 数据口是两颗独立芯片，互不影响。
  • 实测 FT232H 在 lsusb 中显示为 "Future Technology Devices International"（不是 "FTDI" 字样），序列号 FTC7EQO0，PC 端脚本以序列号选设备。

3.6 ILA 在线验证

用 ILA 在真实硬件上抓取状态机行为，确认了三件事：

  • 状态迁移正确：状态编码依次出现 0x005（RAMP，斜坡采集）→ 0x004（过渡）→ 0x0F4（GAP_WAIT，ADC 关闭）→ 0x0F6 ⇄ 0x0F2（USB_TX_IDLE 与 USB_TX_PULSE 交替）。
  • 字节时序正确：probe0 在 00 ⇄ D7 之间跳变，对应存储字 0x00D700D7，说明按 MSB 先发、每字 4 字节。
  • 缓存生效：发送阶段发出的仍是旧值 0x00D7，而此刻 FIR 输出已涨到 0x01AE —— 证明"斜坡期间存、间隙期间发"的缓冲机制确实在工作。

踩坑记录：最初设置的 ILA 触发条件 s_probe3 == 0x001 永远不触发，因为该状态组合（write_n=0 且 chipselect=0 且 muxout=1）在逻辑上不可达。改用可达到的条件（0x800、0x005）后正常。

3.10 第二次录数据：一半问题解决，另一半暴露

新数据 13.50 MB / 5 s（2.70 MB/s），与新的时序预算（4004 字节 / 1510 µs）精确吻合，采样率仍是 2.002 MSPS —— 说明时序那一半改对了。但字节滑移不但没消失，反而更密（814 次 / 5 秒，约每 4145 词一次），帧起点标记命中率只有 6.3%。

排查 usb_sync.vhd 的发送路径，其时序是确定性的（每个时钟弹一个字节），因此丢字节发生在 FT232H 的 USB 事务边界上（245 同步 FIFO 内部为 16 位缓冲，非整包长度的事务收尾容易吞/吐 1 字节）。这是芯片行为，靠调 FPGA 时序难以根治。

3.11 最终方案：每帧自带帧头（magic word）

工程思路的转变：不再追求"字节永不丢"，而是让接收端能从任意位置重新同步。这是所有真实雷达与数据链路的标准做法。

在 control.vhd 中，每帧上传前先发 4 字节帧头：

每帧 = [F0 0D F0 0D] + N 个样本字    （N 由 ramp 长度决定，当前为 1020）

选择 F0 0D F0 0D 的理由：有效样本的高字节只可能是 0x00..0x0F（滤波后幅度在 ±4000 内），因此 0xF0 出现在高字节位置物理上不可能，搜索该魔数零误判。

PC 端相应改为：搜索帧头 → 从帧头后取 N 个样本 → 帧长 N 由帧头间距自动推断（协议自描述，不再与 FPGA 常量硬耦合）→ 逐帧做 range-FFT。

4.1 重点问题详解

P6 / P8："丢一个字节"为什么具有毁灭性

FPGA 每采到一对样本就打成一个 32 位字，拆 4 个字节发出：[A高][A低][B高][B低]。PC 端按"每 4 字节切一刀"还原。一旦链路丢掉 1 个字节，从那一刻起每 4 个字节都横跨两个真实样本，还原结果全部错乱。

迷惑之处在于错位后的字节看起来像"大小端翻转"（02 97 变成 97 02）。区分方法：真的大小端错误是全程一致的，而丢字节是"之前一直正确、某个位置之后全错"。如果误判成大小端去改字节序，将永远修不好。

P7：带宽预算必须算清楚

数据产生率 = 2 MSPS × 4 字节 = 8.0 MB/s，而 USB 实测只有 5.31 MB/s。即使一个字节都不丢，也必然有一部分时间被上传占用。正确做法是把占空比压到带宽之下：本设计用"斜坡 510 µs + 间隙 1000 µs"，每帧 4084 字节，对应 2.70 MB/s，留出约一倍余量。

P9：VHDL 的 range 约束不是硬件约束

signal sample_idx : integer range 0 to MAX_SAMPLES-1 := 0;   -- 0..999
if adc_valid = '1' and sample_idx < MAX_SAMPLES then
    sample_idx <= sample_idx + 1;      -- 综合时不检查 range
end if;

999 需要 10 位，于是综合出的计数器实际能数到 1023。本次 ramp 产出 1020 个样本（小于 1024），因此没有绕回，数据恰好正确——但这是侥幸正确：一旦 ramp 产出超过 1024 个样本，索引会绕回 0 覆盖开头数据，而且是静默损坏。必须改为显式饱和。

七、下一步行动目标与方案建议

7.1 优先级 A：把锯齿换成可编程拍频正弦（NCO）

目标：当前 FFT 看到的是锯齿波的谐波梳，虽然验证了数值链路，但没有"距离"的物理含义。把假信号换成频率可控的正弦后，FFT 峰值位置就等于设定的拍频，才能接上 FMCW 的距离公式。

方案：32 位相位累加器 + 正弦查找表（1024 点，可外挂 coe 初始化），累加器频率字

f_out = (f_word / 2^32) × 40 MHz　例如 100 kHz 对应 f_word ≈ 10 737 418

建议先取 100 kHz（落在 400 kHz 低通通带内、远离直流与抽取后 1 MHz 的奈奎斯特边界），并用一个常量便于修改。

验收标准：平均 range-FFT 的单峰落在设定频率 ±1 个频率分辨单元内（当前帧 1020 点 @2 MSPS，分辨率约 1.96 kHz），带外杂散低于 -40 dBc，帧首标记仍为 0。

工作量：约 30 行 VHDL，一次综合（约 8 分钟）＋ 一次录制验证。

7.2 优先级 B：修掉帧长的静默隐患

问题：见 P9。当前"侥幸正确"依赖 ramp 产出样本数不超过 1024。

方案：把存数逻辑改为真正饱和（if sample_idx < MAX_SAMPLES-1 then sample_idx <= sample_idx + 1），并把 MAX_ADC_SAMPLES 设为 1020 使常量名副其实；同时把 PC 端帧长推断保留为兜底。

验收标准：把 ramp 故意加长到超过 1024 个样本，帧长仍严格等于设定值，数据无覆盖、无跳变。

建议：与 7.1 合并为同一次综合。

7.3 中期目标：慢时间维 → 距离-多普勒图（RD Map）

在 7.1 基础上，让每帧起始相位按固定增量旋转（模拟目标匀速运动引起的多普勒频移），然后对"帧间同一距离单元"做第二次 FFT：

  • 快时间 FFT（帧内）→ 距离；
  • 慢时间 FFT（帧间，同一 range bin 跨 N 帧）→ 速度；
  • 两级结果拼成 RD 图并做可视化。

验收标准：设定"目标距离 + 目标速度"后，RD 图峰值落在理论位置，且与公式 R = c·f_b·T/(2·BW)、v = f_d·λ/2 一致。

7.4 中期目标：配置通路与 MicroBlaze

目前配置通路是旁路的（config_done 恒为 1）。若要由 PC 动态设定斜坡时间、带宽、帧长，需要：

  • 对齐配置包长度（PC 发送 26 字节，FPGA 侧期望 128/256 字节）；
  • 补齐 helloworld.c 的字段解析（当前只解析了 3 个字段）；
  • 恢复 MicroBlaze 对 ADF4158 的 SPI 配置（接真射频时必需）。

7.5 风险与注意事项

风险说明与对策
FT232H 事务边界丢字节当前约每 7~8 帧丢 1 字节，被帧头机制隔离，可用帧 87.2%。若要提升，可让每次 USB 事务长度为偶数包，或把帧头扩展为"魔数 + 帧号 + 帧长 + 校验"，实现坏帧精确定位
帧长与 FFT 点数1020 点不是 2 的幂，且锯齿周期 204.8 点不是整数。换成正弦信号后不影响峰值位置，但若要做零填充或高分辨率谱，建议把帧长取成 2 的幂并与 ramp 时长精确匹配
有符号与增益FIR 输出为有符号且直流增益约 0.273，做幅度/信噪比计算时必须乘回 1/0.273
分布式 RAM 占用1000×32 位采样缓冲占用约 1000 LUT（占全片 40%）。若后续加大帧长，应改用 ram_style="block" 走 BRAM
版本管理仓库当前把 FMCW3.runs / FMCW3.cache / FMCW3.gen 一并纳入跟踪，每次综合都会产生大量无关改动。建议后续加入 .gitignore，只跟踪源码、约束、脚本与文档
